# 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| “可能无法与该版本的 Zotero 兼容” | 确认下载的是正式 `.xpi`，Zotero 版本位于 7.0–10.0.*。早期 0.1.0 缺少必需的 `update_url`，请使用新包；版本大于 10.0.* 时等待兼容性验证。 |
| 没有菜单或设置入口 | 在插件管理器确认插件已启用；禁用后重新启用，必要时重启 Zotero。 |
| “未安装 BabelDOC”或版本不符 | 使用安装器打印的 Python 路径，检查对应环境安装的是 `BabelDOC==0.6.4`。 |
| Python 无法启动 | 填可执行文件而非目录或 `babeldoc` 命令；检查路径仍存在。移动虚拟环境后重新安装。 |
| PDF 未下载到本地 | 先在 Zotero 中打开原附件完成下载。 |
| 没有附件写入权限 | 群组库需要允许编辑条目与文件；只读库无法保存结果。 |
| 初始化很久 | 首次模型/字体下载可能较慢；检查网络，取消后重试。 |
| API 请求失败 | 检查包含 `/v1` 等必要路径的基础地址、模型名、密钥、权限、余额和限流；确认支持 Chat Completions。 |
| 出现 CoreML 退出错误 | 0.1.1 起固定 ONNX CPU 模式；确认更新包而非旧版。 |
| Windows 原生依赖加载失败 | 检查使用匹配系统架构的 Python 3.12、BabelDOC 依赖及所需 Microsoft Visual C++ 运行库。Windows 桌面仍待实测。 |
| 显示“结果保留于…” | PDF 已生成但导入失败；打开提示目录，手动拖入 Zotero，保留文件直至确认导入成功。 |
| 结果没有自动打开 | 从文献的译文/双语子附件打开；默认优先打开双语。 |
| 翻译内容或版面不理想 | 换模型、用小页码范围排查；扫描件试 OCR。排版依赖 BabelDOC，模型质量与本插件流程测试是不同事项。 |
| 收不到自动更新 | 旧本地 0.1.1 须手动安装一次 0.1.2；检查能否访问 GitHub 的固定更新清单。 |

提交 [Bug](https://github.com/ptiris/zotero-babeldoc/issues/new?template=bug-report.yml) 时提供 Zotero/插件/Python/BabelDOC 版本、操作系统和架构、复现步骤、去除敏感信息后的错误。不要提交 API Key、含密钥的 URL、私人 PDF、数据库或缓存。可用自制无敏感文本 PDF 复现。

[发布指南](publishing.md) 另含 Actions、版本号和更新清单的维护问题。
